## 1. Cómo explicar CoreCheck (elevator pitch)

**En una frase**

> CoreCheck es un Quality Gate unificado para CI/CD: audita una URL (seguridad, accesibilidad WCAG, performance, privacy, SEO) y guarda el historial por cliente en un dashboard — no es solo un HTML suelto por corrida.

**Qué compra el cliente**

- Un gate de PR con exit codes estables (0–4).
- Evidencia accionable (HTML, SARIF, JSON, PDF).
- Historial por tenant: trends, score delta, Diff entre corridas.
- Integridad verificable (hash / HMAC).

**Qué NO es**

- No sustituye un pentest ofensivo.
- No es un IdP / MFA / SSO.
- No es “vamos a construir el dashboard” — el Viewer **ya existe**.

**Analogía simple**

> Como un “semáforo de calidad” en cada PR, más un historial médico del sitio: ves si mejoró o empeoró entre deploys.

## 5. Detalles técnicos útiles

### Arquitectura en dos piezas

1. **CLI (monorepo `src/`)** — Playwright, gate, reporters.  
2. **`corecheck-api`** — Express Control Plane: ingest, tenant, Viewer.

### Flujo que probamos hoy

```text
npx tsx src/cli/index.ts run --url https://example.com
  --skip-license --upload --api-key <KEY> --upload-url https://corecheck-api.onrender.com
       → POST /api/reports (201 + reportId)
            → Neon Postgres
                 → /viewer/ (Runs=2, trends, Diff last 2)
```

### Secrets (dónde viven)

| Variable | Dónde |
| :--- | :--- |
| `CORECHECK_API_KEY` | Render → Settings → Environment (misma key en CLI y Viewer) |
| `DATABASE_URL` | Render (Neon connection string) |
| `CORECHECK_REPORT_HMAC_SECRET` | Render |
| Key local en PowerShell | `$env:CORECHECK_API_KEY` / `$KEY` — **no** subir a Git |

### Comando de upload (referencia)

```powershell
cd C:\Users\maryf\Documents\CoreCheck
$API = "https://corecheck-api.onrender.com"
$KEY = "<copiar de Render Environment>"
npx tsx src/cli/index.ts run --url https://example.com --skip-license --upload --fail-on HIGH --max-pages 2 --api-key $KEY --upload-url $API
```
